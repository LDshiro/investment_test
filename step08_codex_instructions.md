## 2. Current workflow to consolidate

The repository already has separate commands roughly like:

```bash
python -m leadlag.cli run-batch --config configs/profiles/shadow_corrected_batch_60d_local.yaml
python -m leadlag.cli validate-shadow-replay --batch-dir <batch_dir> --config configs/validation/shadow_replay_v1.yaml --output-dir <validation_dir>
python -m leadlag.cli weekly-review --batch-dir <batch_dir> --output-dir <weekly_review_dir>
python -m leadlag.cli weekly-gates --review-dir <weekly_review_dir> --rules-config configs/review/weekly_rules_shadow_pre_live_v1.yaml --output-dir <weekly_gates_dir>
python -m leadlag.cli render-runbook --config configs/ops/runbook_shadow_v1.yaml --output-dir <runbook_dir>
```

Step 08 should create one operations-level command that orchestrates these steps.

Preferred new command:

```bash
python -m leadlag.cli shadow-ops --config configs/ops/shadow_ops_legacy_60d_local.yaml
```

Also add a canonical opt-in profile:

```bash
python -m leadlag.cli shadow-ops --config configs/ops/shadow_ops_canonical_60d_local.yaml
```

## 3. Add config files

Add two operations profiles:

```text
configs/ops/shadow_ops_legacy_60d_local.yaml
configs/ops/shadow_ops_canonical_60d_local.yaml
```

Suggested schema:

```yaml
ops:
  name: shadow_ops_legacy_60d_local
  mode: shadow_only
  artifact_root: artifacts/shadow_ops
  stop_on_stage_failure: true
  overwrite_existing: false
  timestamp_outputs: true
  operator_digest: true

stages:
  validate_data_contract:
    enabled: true
    bundle_dir: data/normalized/corrected_bundle
    contract: configs/data_contracts/corrected_bundle_v1.yaml

  run_batch:
    enabled: true
    config: configs/profiles/shadow_corrected_batch_60d_local.yaml

  validate_shadow_replay:
    enabled: true
    config: configs/validation/shadow_replay_v1.yaml

  weekly_review:
    enabled: true

  weekly_gates:
    enabled: true
    rules_config: configs/review/weekly_rules_shadow_pre_live_v1.yaml

  render_runbook:
    enabled: true
    config: configs/ops/runbook_shadow_v1.yaml
```

For the canonical profile, use:

```yaml
stages:
  run_batch:
    config: configs/profiles/shadow_corrected_canonical_batch_60d_local.yaml
  validate_shadow_replay:
    config: configs/validation/shadow_replay_canonical_v1.yaml
```

The exact schema can differ, but document it.

## 4. Implement orchestration module

Add a module such as:

```text
src/leadlag/ops/shadow_ops.py
```

It should:

1. Load the operations config.
2. Create a unique run directory under `artifact_root`.
3. Execute enabled stages in order.
4. Stop on failure by default.
5. Record stage status, command/config used, output directory, start/end timestamps, and error text.
6. Locate the batch directory produced by `run-batch`.
7. Pass that batch directory into replay validation and weekly review.
8. Pass weekly review output into weekly gates.
9. Write a human-readable `operator_digest.md`.
10. Write a machine-readable `shadow_ops_summary.json`.

Prefer calling internal Python APIs if stable and available. If the existing implementation is mostly CLI-oriented, it is acceptable to call subprocesses, but capture stdout/stderr and return codes.

Do not silently ignore failures.

## 8. Operator digest requirements

`operator_digest.md` should be concise and useful for this chat.

Include:

- ops run id
- generated timestamp
- profile used
- legacy or canonical mode
- all stage statuses
- batch total / completed / failed days
- GO / WARN / STOP counts
- weekly latest status
- promotion assessment status
- main promotion failed checks
- canonical reconciliation max diff bps, if applicable
- artifact paths
- human action required: yes/no
- recommended next action, limited to review wording only

Do not instruct automatic live trading.
